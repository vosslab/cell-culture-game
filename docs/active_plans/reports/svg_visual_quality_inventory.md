# SVG visual-quality inventory

## Scope and evidence

This M1 ledger inventories the current retained `assets/equipment/**/*.svg` tree. It is a
review record, not product metadata: `content/objects/` remains the authority for object
identity and `content/**/scenes/` remains the authority for placement. The source tree contains
130 retained SVGs after the 2026-08-26 recovery and second-pass ownership repair. The M1 dispositions preserve the
pre-rebuild planning judgment; they are not claims about current visual acceptance.
`generated/svg_manifest.ts` supplies the current render mode;
object YAML supplies direct consumers; scene YAML supplies direct placement contexts.

Observed columns are **SVG**, **Role**, **Family**, **Consumers/context**, and **Mode**.
**Disposition** and the priority in **Handoff note** are review judgments. P0 protects a
separate result-interface boundary; P1 identity/projection/state-ownership defects outrank P2
composite/state coherence, which outranks cosmetic finish. Each scene context is regenerated
from every object YAML `visual_states` asset binding and from every direct placement in
`content/base_scenes/*.yaml` plus `content/**/scenes/*.yaml`; it does not assume a default or
final state is the only reachable visual form. `base [N: ...]` and `authored [N: ...]` report
the exact number of distinct direct placement contexts. For readability, each bracket lists the
first three scene names in sorted order and then the exact remaining count. `none in base or
authored scene placements` is reserved for a bound asset whose object has no such placement.

## Vocabulary

| Field       | Closed review vocabulary                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Role        | complete physical object; state family; overlay or composite fragment; evidence or observation graphic; protected result interface |
| Disposition | KEEP; REPAIR; REDRAW; REUSE_CANONICAL_FORM; OVERLAY_REVIEW_IN_COMPOSITE; DEFERRED_RESULT_UI                                        |
| Mode        | inline DOM means the manifest requires internal SVG access; img eligible means the manifest permits opaque image rendering.        |
