# M2 Servier counterpart sweep

Date: 2026-08-25

## Scope and method

This is the M2 provenance ledger for the current retained equipment tree. The
inventory command below now accounts for 130 SVGs: 101 physical equipment assets, 22
overlays or observation/feedback assets, and seven protected result interfaces.
The category is recorded so physical equipment is not conflated with a scene
overlay or an application-owned result UI.

```sh
find assets/equipment -type f -name '*.svg' -printf '%P\n' | sort
find OTHER_REPOS/bioicons/static/icons/cc-by-3.0 -type f \
  -path '*/Servier/*.svg' -printf '%P\n' | sort
```

The second command returned 1,373 local Servier SVGs. For each physical asset,
the search began with the 30-file `Lab_apparatus/Servier/` directory, then used
the wider local Servier tree for its object-class terms. `servier_source` means
the retained asset already adapts that source. `servier_adjacent` means the
named source is a construction reference for the stated housing, vessel,
opening, or mechanism; it does not claim retained source geometry. A
`no_servier_source` result is bounded to the stated terms and the local tree.

Protected result UI is recorded for coverage, but is out of this visual-art
milestone. Its ownership boundary is established by
[the embedded-interface audit](../audits/svg_embedded_interface_scope.md).

## Coverage and open identity questions

- Coverage is 130 of 130 retained SVGs: 101 physical equipment, 22 overlays or
  feedback/observation assets, and seven protected result interfaces.
- Direct-source rows are already attributed in `assets/equipment/SOURCES.md`.
  The derived gel-cassette state rows are covered by the same canonical
  `gel-electrophoresis.svg` adoption; no duplicate attribution rows are needed.
- `cell_counter_instrument.svg` is a generic counter and `hba1canalyzer.svg` is
  only a housing/display construction reference. Do not elevate it to direct
  provenance without a future geometry reuse decision.
- `plate_reader_*` is adjacent to a spectrophotometer, not a direct source: the
  reader's microplate mechanism needs its own reference board before redraw.
- P20, P200, and P1000 are `no_servier_source`: the local generic micropipette
  establishes actual direct provenance for P10 only. Their M7 construction uses the
  bounded Eppendorf/Gilson anatomy evidence in the M4 board unless a later redraw
  documents a specific reused Servier structural feature.
- `rocking_shaker_*` is not an agitator adoption. Servier's `agitator.svg` does
  not establish the rocking platform mechanism, so the current DBCLS source
  remains the provenance record.
