# Protocol walkthrough integrity recovery

## Purpose

This plan completes the student-path recovery for protocol packages that could
reach a visual or scientific dead end. It keeps the existing YAML, runtime,
SVG, layout, visible-UI, and learning-block invariants in
[PRIMARY_CONTRACT.md](../../PRIMARY_CONTRACT.md). It does not change that
contract.

The delivered behavior is one coherent rule: a protocol declares only valid
state, the browser shows the exact next action, an incorrect visible sibling is
rejected, and the generic walker proves the same path a student uses.

## Scope decisions

| Decision                                            | Status       | Why this version succeeds                                                                                                                          |
| --------------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add root `initial_state`                            | In scope     | Directly launchable mini-protocols start with the scientific prerequisite that their first step needs.                                             |
| Preserve state through a runner                     | In scope     | One session archive prevents a scene switch or later mini-protocol from erasing produced material.                                                 |
| Restrict runners to unique direct leaves            | In scope     | One package list has one order, one session boundary, and one walkthrough accounting path.                                                         |
| Make exact subparts visibly clickable               | In scope     | A learner can identify and click the authored well, lane, or rack slot rather than a parent-object shortcut.                                       |
| Repair Cell MTT and SDS-PAGE state chains           | In scope     | The two highest-impact scientific chains now have quantities, order, sources, destinations, and visible states that agree.                         |
| Add a new interaction vocabulary or contract field  | Out of scope | Existing `ObjectStateChange`, structured subparts, and root protocol fields express the required behavior without expanding the closed vocabulary. |
| Add drag curriculum                                 | Out of scope | No repaired protocol requires it; the click, adjust, select, type, and timed-wait paths cover this release.                                        |
| Add a plate-reader result or IC50 analysis artifact | Out of scope | The repaired endpoint reaches a correctly specified 560 nm readout; analysis is a separate learning block.                                         |
| Model a course-specific microscopy observation      | Out of scope | A scientifically valid image or assessment representation needs a separately approved learning block.                                              |
| Add responsive or touch corpus certification        | Out of scope | This release proves the standard browser student path and does not claim a device range not yet specified.                                         |

Targeted unit, schema, content, and focused browser tests are the first
acceptance evidence for this recovery. Run the direct and runner browser paths
through the built application with these concrete commands:

```bash
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol trypan_blue_counting
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol mtt_reagent_prep
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol mtt_plate_reaction
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol mtt_solubilization_readout
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol plate_drug_treatment_drug_addition --wrong-order
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol cell_culture_full
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol cell_culture_full --wrong-order
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol sdspage_prepare_sample_mix_batch
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol sdspage_heat_denature_samples
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol sdspage_load_protein_ladder --wrong-order
node tests/playwright/e2e/protocol_walkthrough_yaml.mjs --protocol sdspage_load_samples_batch --wrong-order

```

The final release gates were executed after the direct matrix:

```bash
./run_fast_checks.sh
bash run_playwright_tests.sh
git diff --check
```

`run_fast_checks.sh` owns the canonical `build_github_pages.sh` production build,
so the build is both explicit in the script and included in the recorded gate.
